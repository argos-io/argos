## 1. 定位与已确认职责

站点交付物是管理端生成的最终成果，以源代码为核心。同一套源码支持 Cloudflare 和用户的标准 Node.js 环境；用户可以接手维护，也可以使用管理端提供的 Cloudflare 托管服务。

已确认托管使用客户自有 Cloudflare 账户，由团队授权代管；首版支持完整数据导出，并可恢复到 Cloudflare 或 Node.js。该要求包含实际恢复能力，不仅提供源码运行目标；具体数据边界、恢复方式和责任矩阵按下文提案细化，见 [ADR-0010](adr/0010-customer-owned-hosting-and-portable-data.md)。

管理端永久仅供内部团队使用，不向客户交付或开放。客户获得站点交付物及约定的托管服务，使用站点自身的独立业务后台经营站点。

交付程序负责站点业务运行与开放 API，不包含生成站点或新插件的代码生成过程。新增插件由管理端生成或选择、纳入构建并发布后，才成为交付程序的一部分。

已确认交付物必须自带独立站点业务后台；插件除业务功能外，还向业务后台注册对应管理功能。详见 [站点业务后台](business-admin.md)。

首个管理员通过受保护的初始化页面建立，使用部署时提供的一次性初始化凭据，选择并验证登录身份后创建；成功后凭据失效，入口不再创建管理员。后续后台成员由具备成员管理权限的人邀请并分配权限，受邀者验证身份后加入。后台支持按其有效配置开放的 Google、微信网站扫码和邮箱一次性登录链接；初始化、邀请与登录能力均随业务后台交付，不依赖访客用户管理插件，具体凭据和渠道配置契约待设计。

每个交付站点必备后台成员登录与授权。访客注册、登录和账号管理由可选用户管理插件提供；仅有企业展示与客服的站点可以不安装该插件，后台仍可正常使用。CRM 和电商均强制依赖用户管理，遵循自动安装、联动启用和停用保护规则；所有电商站点统一要求买家登录后才能下单，见 [ADR-0006](adr/0006-required-admin-optional-visitor-accounts.md) 与 [ADR-0007](adr/0007-required-plugin-dependencies.md)。

交付物由固定版本核心、选定插件、主题及组装配置构成。操作人按需求编辑插件和主题，不修改核心；具体核心依赖与源码交接方式待设计。主题是一类插件，负责页面、布局、视觉和业务能力的呈现，详见 [主题与操作边界](themes.md)。

## 2. 运行与扩展要求

- 最小运行时通过插件扩展业务功能，保持核心尽量小。
- 每站后台必需 RBAC 基础插件，随后台构建时自动安装、运行时联动启用；依赖期间不得停用，授权缺失或故障时不放行受保护操作。核心保留统一服务端检查入口，具体角色模型与契约见 [RBAC 设计](rbac.md)。
- 插件构建时安装，运行时控制已安装插件是否启用，详见 [插件生命周期](plugins.md)。
- 运行时启用插件时自动联动启用已安装的必需依赖，检查配置与就绪状态；依赖未就绪时不将依赖者标记为已启用。
- 仍有已启用插件必需依赖某插件时，拒绝停用该插件并列出依赖者；要求先停用依赖者，不自动联动停用。
- 注册插件的操作人负责插件安全性；运行时按可信插件模型设计。
- 站点业务 API 与维护 API 是交付程序的对外契约，管理端通过这些接口完成相应维护。
- 插件的业务实现与后台扩展一起纳入构建，运行时按插件启用状态开放相应管理能力。
- 同一源码可以通过不同入口、构建配置或适配满足两个运行目标；具体数据库、存储和任务执行机制待设计。
- 可维护性需覆盖源码接手、项目定制、插件升级、业务数据及故障恢复；具体保证见总览与各业务文档中的待确认项。

一个前台账号支持登录后验证、主动绑定 Google、微信或邮箱，使用任一已绑定方式登录都共用账号及订单。目标身份已绑定另一账号时，拒绝绑定并提示使用原账号；首版不提供账号合并，两个账号的身份与业务数据保持不变。解绑规则待设计，见 [账号与登录身份决策](adr/0008-site-accounts-and-login-identities.md)。

## 5. 管理端与站点业务后台的区分

管理端负责需求、代码生成、工程与版本、构建、部署和跨站点维护。站点业务后台必须随源码交付，面向单个站点的业务经营与日常操作，独立于管理端运行。

管理端不是客户侧业务后台，也不作为客户交付软件的一部分。内部团队可按服务约定代为执行维护；已确认客户自行修改交付源码后，不要求支持重新交由管理端继续生成和升级。客户可自行维护其源码版本，源码运行、配置和交接说明仍属于可维护性交付要求。

通过业务后台维护内容、商品、订单、用户、CRM 或已开放配置，不等同于源码修改；该类正常业务操作继续按对应 API 和插件规则进行。

业务后台由通用后台框架和插件注册的管理功能组成，业务内容随启用插件变化。管理端是否额外提供统一的跨站点业务界面仍待确认，该能力不替代交付站点自身的业务后台。

## 6. 候选验收

- 同一份源码部署到两个运行目标，所选业务插件与运行时 API 满足同一契约。
- 交付站点无需代码生成 agent 或管理端生成服务即可提供已部署业务。
- 接手者可按文档修改站点与插件、构建和部署，交付物包含完成这些操作所需的工程信息。
- 已安装插件可以运行时启停；未安装能力只能经工程变更、构建和发布加入。
- 账号、内容、订单、支付及 CRM 按对应模块契约运行，不依赖管理端保存唯一业务事实。
- 开放 API 允许托管服务与其他已授权调用方完成约定的运行时维护。
- 管理端不可用时，仍可通过站点业务后台进行约定的日常操作；插件的管理界面与 API 一并交付。
- 未安装访客用户管理插件的企业展示与客服站点，仍能通过后台成员登录与授权完成日常管理。
- 安装、启用、停用插件时，其业务后台入口与操作按约定变化，插件能通过注册扩展通用后台。
- 页面和业务定制可通过主题与插件实现，操作人构建交付站点无需修改核心代码。

第 7–8 节保留原完整产品的可评审功能、交付与验收基线；当前 demo 的范围和完成标准以需求第 8 节为准。未确认的细项不能因列入提案就视作已接受；以下用例尚未执行。

### 7.2 交付包与发布门槛

交付包建议包含站点运行与构建所需源码、主题、选定插件、固定核心依赖、锁定清单、迁移与初始化工具、非密钥配置样例、部署/备份/恢复说明，以及对应验证记录。固定依赖必须随交付可获取，不能只留下接手者无法访问的内部仓库版本号。内部管理端及 agent 执行器不属于客户交付包。

交付版本关联不可混用的源码修订、组装清单、核心/插件/主题版本、数据模式版本、构建产物与验收结果；操作人选择交付的版本不被后续生成任务替换。预览采用独立测试配置与数据，不默认复用生产凭据、交易端点或写入生产数据。

未来实施支付、物流和客服等业务模块时，再冻结相应服务商及必要业务规则；本期不因后置模块缺少服务商而阻塞。对实际纳入实施的模块，缺少渠道配置或真实契约验证的能力标为阻塞，不按空实现、模拟响应或页面截图判为通过。外部服务的沙箱验证与实际生产配置就绪分别记录。

| DL1 | 当参考组装 A、B 的固定源码分别部署到 Cloudflare 与 Node.js 时 | 四组记录均覆盖真实后端与后台行为，同组装使用相同版本和业务语义 |
| DL2 | 当另一位开发者在干净环境按交付说明构建、初始化并运行源码时 | 所需依赖可获取，不需要内部管理端或 agent 持续在线；源码与构建版本可核对 |
| DL3 | 当 A 未安装访客用户管理，B 仅选择依赖它的业务能力时 | A 的后台初始化/登录/授权正常；B 自动补齐并启用依赖，拒绝停用仍被依赖的能力 |
| DL4 | 当前后台登录渠道分别配置、缺失或无效时 | 各渠道独立生效；前台首次注册、绑定与冲突拒绝符合已确认规则，不自动成为后台成员 |
| DL5 | 当使用只读成员、角色管理者与所有者操作后台时 | 允许和拒绝均由服务端验证，纯角色、多角色及最后所有者保护符合已接受契约；RBAC v1 建议需先评审 |
| DL6 | 当 B 完成浏览加购、登录下单、支付、履约和售后，并重放支付/退款事件时 | 订单、资金、库存及履约记录一致，不重复扣款/退款；并发与超时按冻结后的业务规则处理 |
| DL7 | 当 CRM 管理无登录账号的联系人并关联订单、导入或合并记录时 | 联系人与登录账号职责分开，不能据邮箱相同创建已验证身份或转移订单，访问范围与来源可追溯 |
| DL8 | 当已安装插件启停、依赖未就绪或升级失败时 | 页面、后台、API 和任务按已接受生命周期变化，在途交易和数据保留有明确结果 |
| DL9 | 当操作人检查预览并选择指定版本交付或托管发布时 | 记录与该源码、清单和产物一致，后续任务不覆盖选定版本；新代码仍只修改插件、主题及组装配置 |
| DL10 | 当获授权操作者导出完整站点数据时 | 包含第 8 节的业务、关系、文件及恢复元数据，有一致性切点与完整性报告，不只导出展示 CSV |
| DL11 | 当将 B 的数据包导入全新目标存储，分别验证 Cloudflare→Node.js、Node.js→Cloudflare 及两种同平台恢复时 | 原账号/成员/角色、订单/库存/CRM 关联及文件完整，目标不通过继续连接源库伪装完成恢复 |
| DL12 | 当导出或迁移涉及在途事件、持久任务和外部交易时 | 记录一致性切点及在途状态，目标初始暂停外部副作用，按已验证对账流程恢复，不重复支付、退款或发货 |
| DL13 | 当数据包缺文件、校验失败、版本不兼容或含跨站点关系时 | 恢复拒绝切换并报告原因，不静默忽略模块，不将部分导入报告为成功 |
| DL14 | 当恢复成员和 RBAC 数据时 | 受保护系统角色及有效所有者约束成立，旧会话/提交上下文不能直接复用，不重开首个管理员初始化 |
| DL15 | 当客户撤销团队的 Cloudflare 代管授权时 | 后续团队维护明确失败并记录，系统不主动删除或停用客户已有资源；源码、数据和客户接管路径不依赖代管继续有效 |
| DL16 | 当部署指定了错误客户账户、资源映射或授权范围不足时 | 在变更前校验并拒绝，不能落到另一客户或平台公共账户；日志不包含代管凭据 |
| DL17 | 当代码升级或数据迁移失败并演练恢复时 | 分别说明代码回退与数据恢复，记录实测维护窗口、可恢复切点及数据变化，不把代码回退视为数据已回退 |
| DL18 | 当代管终止、客户自行修改源码或管理端不可用时 | 客户仍按交付说明经营和维护站点；不要求修改源码后回流管理端，也不将内部任务历史作为业务恢复依赖 |

以上为待评审验收，不是测试结果；相关业务合同与适配器尚未选择或实现时不能宣称首版已经具备交付条件。

## 8. 客户账户托管与完整数据交付

### 8.1 已确认决策与责任建议

已确认的产品目标为 Cloudflare 资源在客户自有账户中，团队经授权代管，完整导出并支持恢复到 Cloudflare 或 Node.js。当前 demo 已确认验证实际演示数据的最小完整恢复闭环，不据此启动生产代管或先实现所有业务的恢复。以下责任分配、格式、流程和验收是完整产品的建议，不是已经签订的运维或服务等级承诺。

| 对象 | 客户责任建议 | 团队责任建议 |
| --- | --- | --- |
| Cloudflare 账户及资源 | 持有账户控制权、批准授权与必要资源，处理账户自身的验证及计费 | 在授权范围内部署维护，记录账户/站点/资源映射，不使用平台统一账户作为默认资源归属 |
| 域名、支付、物流、身份与邮件服务 | 提供业务所需账户、域名控制与合法配置，确认服务商费用和准入 | 交付配置说明及就绪检查，明确需要客户处理的域名和外部服务切换 |
| 源码与版本 | 接收源码、依赖及记录；自行修改后的版本由客户接管维护 | 交付可构建工程，内部持续维护时保留项目定制和升级记录 |
| 备份、导出与恢复 | 确认备份保留、存放位置及恢复窗口，保管客户持有的恢复材料 | 提供完整导出/恢复工具、数据边界和演练记录；代管期按约定运行备份并报告失败 |
| 日常运营 | 通过本站后台维护内容、交易和客户数据 | 提供约定支持；基础设施代管不自动授予站点 `owner` 或无限业务操作权 |
| 终止与接管 | 轮换或撤销代管和维护凭据，指定接管方 | 交接最终版本、数据、资源清单与未完成事项；不因终止服务自动删除客户资源 |

客户自有 Cloudflare 账户不等于上述所有第三方账户、收费和服务责任都已确认；表中的域名及第三方分工仍需交付约定。云账户授权与站点维护 API 授权分别配置、撤销和审计，不将云凭据复用为站点后台所有者凭据。

授权接入建议采用客户批准、可撤销的受限凭据；管理端安全保存凭据引用，不写入源码、构建日志或交付样例。首次接入先核验账户与实际资源范围，权限粒度和端点兼容性按选定 Cloudflare 服务验证，不能把账户级权限描述为已经实现单站隔离。轮换、失效和撤销后停止新的代管操作，已有运行资源不因系统主动清理而丢失。

### 8.2 完整数据的建议边界

完整导出覆盖该站点持有的全部可持久化业务事实及恢复必需状态，按所安装插件列清单，不要求导出内部管理端的项目任务或 agent 会话。

| 类别 | 需要覆盖的内容 | 恢复约束建议 |
| --- | --- | --- |
| 站点与配置 | 稳定站点 ID、非密钥设置、主题/插件配置、插件启用状态、发布与模式版本 | 记录配置及依赖版本；目标资源绑定、域名和密钥单独映射 |
| 身份与授权 | 前台账号、验证身份关联、核心后台成员、角色/权限关联、所有者及审计、初始化完成事实 | 保留稳定 ID 与验证事实；目标生成新授权/会话世代，失效的登录链接、邀请和会话不复活 |
| 展示与文件 | 内容、媒体、附件、文件元数据、逻辑文件引用及完整性校验 | 实际复制文件到目标存储，不能只保留指向旧账户的下载 URL |
| 电商 | 商品/SKU、价格、库存与变动、服务端账号购物车及最后修改/到期信息、客户地址、订单快照、支付/退款与履约/售后记录 | 保留金额精度、币种、数量、状态、服务商交易 ID 和关系；不重建或重新提交历史交易，不因恢复重置购物车保存期限；仅在浏览器保存的匿名购物车不属于服务端备份可恢复对象 |
| CRM | 联系人、字段、标签/分群、负责人、跟进、互动、合并历史和业务关联 | 按原稳定 ID 恢复，不以重新匹配邮箱重建账号或订单归属 |
| 可靠性状态 | 已持久化事件、待处理任务、业务幂等记录、在途业务命令和处理进度 | 目标先暂停执行，核验后按原命令 ID 对账和恢复；避免把迁移当作新交易 |

第三方服务商内部的资金余额、完整客服原始会话、物流账户和不可导出的平台数据不由站点凭空生成。站点已持有的副本、引用及交易状态必须导出，并逐项列明外部依赖和服务商侧的接管操作；不能把缺失的站点自有数据统一归因于第三方限制。

OAuth/微信应用凭据、支付和云 API 密钥等通过独立受控配置交接，数据包只记录所需配置引用与就绪检查。保留账号身份关联不等于可在换用另一个第三方应用后自动证明身份；恢复须核验原应用/账号兼容性或进入明确身份恢复流程，不按相同邮箱自动重绑。会话、一次性链接和租约等短期执行状态不作为可复活的业务权限导入。

### 8.3 导出包与恢复流程建议

包内使用版本化、可跨适配器读取的逻辑数据，而非只交付某种数据库的专用快照。建议包含站点与版本清单、各模块数据及数量摘要、文件清单与校验值、关系检查报告、外部依赖/配置需求、导出切点和在途状态报告。核心及插件均须提供对应版本的导出/恢复契约，导出成功前检查全部已安装数据模块，禁止静默跳过不认识的插件。

包按客户数据保护要求加密和授权交接；校验值用于完整性检查，不代替访问控制。目标读取相同模式版本，或执行显式已验证的迁移；不承诺任意旧版本、任意新数据库或第三方插件都能无需适配直接导入。

建议先支持受控维护窗口内的一致性导出和恢复：

1. 固定源码、清单及模式版本；核验源站、目标站与资源归属，列出全部数据模块和配置依赖。冻结新写入及任务执行，协调业务、文件与持久事件的一致性切点；未完成的一致性导出不得标成功。
2. 导出数据和实际文件，校验数量、关系、校验值及在途事项。外部回调不能在尚未持久化时确认成功；切换期间的事件保留、重试与对账按选定服务商契约处理，无法保证时阻止交易恢复上线。
3. 在全新目标资源中校验版本及配置，先以维护模式导入全部模块和文件；导入失败不覆盖仍在运行的源站，不报告部分成功。生成新的授权世代、会话凭据和执行租约，保留已消费的初始化状态。
4. 核对关联、文件、有效所有者、业务汇总和历史交易；目标保持副作用暂停，在途支付/退款/发货按原服务商记录及幂等 ID 核对后再恢复，不能无条件重放。
5. 客户确认目标检查结果后切换域名/入口及服务商回调配置，核验旧实例和旧任务已停止写入；再开放目标新业务。切换失败按已演练方案恢复入口，不能让两端同时执行同一交易命令。
6. 交接切点、验证结果、未完成事项及保留的源站回退资源；源数据的最终清理由客户确认后单独执行，不属于自动迁移收尾。

Cloudflare→Node.js、Node.js→Cloudflare 及同平台恢复均纳入首版验收；每种所选存储适配器必须证明可导入全新目标，不能仅演示继续访问源数据库。允许先以维护窗口保证一致性，在线增量迁移和自动零停机切换不作为本轮默认承诺。

### 8.4 尚需冻结的运维参数与依据

备份频率与保留天数、数据量上限、恢复耗时/可接受丢失窗口、维护窗口、监控响应、费用与服务终止后的材料保留周期仍需确定。实施前根据代表性数据规模实测并写入交付约定；不得把人工完整导出功能当作已落实周期性备份或恢复时限。

[Cloudflare API token 创建说明](https://developers.cloudflare.com/fundamentals/api/get-started/create-token/)支持按策略选择账户/区域资源和权限，并配置到期或来源限制；[权限目录](https://developers.cloudflare.com/fundamentals/api/reference/permissions/)用于核验具体权限。查阅于 2026-11-08。客户账户归属来自用户确认，受限凭据接入及上述迁移/运维流程为本项目提案，不表示已经开通账户、配置授权或验证全部 Cloudflare 服务能力。
