# 源码为核心交付物，托管作为独立服务

源码交付和托管交付都需要支持，同时必须考虑交付后的维护。选择以站点源代码作为核心交付物，同一套源码支持 Cloudflare 与用户的标准 Node.js 环境；托管作为独立服务，调用 Cloudflare 平台能力部署站点，并通过交付程序的开放 API 执行维护。

这一选择将站点运行能力与托管运营责任分开，允许用户接手源码，也允许平台提供持续部署与维护服务。运行时和插件的设计需要考虑两个运行目标，不能把托管服务中的专有状态当作交付站点唯一的业务实现。

## 后续设计约束

- 区分 Cloudflare 平台 API 与交付程序提供的站点开放 API，分别定义其操作范围。
- 明确平台差异如何适配，以及站点开放 API 的版本和插件扩展契约。
- 两种运行目标的具体入口、构建产物、依赖和配置尚待设计。
- 后续由 [ADR-0010](0010-customer-owned-hosting-and-portable-data.md) 确认首版完整数据导出并恢复到 Cloudflare 或 Node.js，以及客户自有 Cloudflare 账户授权代管；具体交付机制和运维服务等级按该决策引用的提案细化。
