# 后台成员登录与授权必备，访客用户管理按需安装

用户选择按需安装访客用户管理：所有交付站点都具备业务后台成员登录与授权，面向访客的注册、登录及账号管理由可选用户管理插件提供。仅有企业展示和客服的站点可以不安装访客账号能力，仍能通过业务后台维护内容与配置。

这一选择使业务后台的可用性独立于访客账号需求。不安装或停用访客用户管理插件，不影响后台成员登录与授权；该边界不代表同意绕过其他业务插件的依赖校验。

首个管理员通过受保护的初始化页面建立，使用部署时提供的一次性初始化凭据，选择并验证登录身份后创建；成功后凭据失效，入口不再创建管理员。后续后台成员采用邀请制：具备成员管理权限的人邀请并分配权限，受邀者验证身份后加入。初始化与邀请均属于必备后台成员基础能力，不依赖可选访客用户管理插件。

后台成员支持 Google、微信网站扫码和邮箱一次性登录链接，按后台有效配置开放。渠道验证成功后仍检查成员资格及权限，不沿用前台首次登录自动注册为后台成员；这些登录能力必须在未安装访客用户管理插件时仍可使用。

## 后续设计约束

- 后台成员基础能力随站点交付并独立于内部管理端运行。
- 初始化凭据只授权首个管理员的建立，所选身份仍需完成登录验证；凭据生成与交付、有效期、一次性消费与初始化完成记录、失败重试和恢复机制继续设计。
- CRM 与电商对访客用户管理的强制依赖、自动安装、联动启用和停用保护已由 [ADR-0007](0007-required-plugin-dependencies.md) 确认；所有电商站点买家下单必须登录，联系人与账号的关联规则仍需细化。
- 后台成员与访客账号的业务职责分别定义；前台允许登录后验证、主动绑定多种身份到同一账号，见 [ADR-0008](0008-site-accounts-and-login-identities.md)。前后台已确认支持相同三类登录渠道，不预设共用应用凭据、会话或数据表；底层认证代码复用方式及账号关联仍待设计。微信接入配置、邮件服务与链接生命周期见 [用户管理与 CRM](../users-crm.md) 的待确认项。
- 前台用户首次完成身份验证、尚无对应本站账号时自动创建账号并登录；自动注册不授予后台成员身份。后台后续成员经邀请并验证身份后加入，具体邀请契约与成员生命周期待设计。
- 本决策只确定账号能力边界，不批准完整的最小核心清单、插件代码接口或具体包结构。

需求与候选契约见 [用户管理与 CRM](../users-crm.md) 和 [站点业务后台](../business-admin.md)。
