# 首版同一电商站点支持多种交易币种

分期更新：本决策保留为后续电商产品要求，电商已移出第一期可行性 demo，不继续细化其待定边界，见 [ADR-0012](0012-feasibility-demo-first.md)。

用户在 Q59 选择 B：首版同一站点支持多种交易币种，商品可提供多币种价格，订单可使用不同币种付款，不采用每站只允许一种交易币种的限制。商家所在地和销售目的地继续灵活配置。

这要求定价、订单与支付领域明确承载币种，而非仅在主题中换算展示价格。历史交易及数据导出需要保留原金额、币种和成交快照，不因后来修改站点配置重新解释历史金额。

用户在 Q60 进一步选择 A：首版每个 SKU 按币种独立维护售价，不采用基础售价经汇率自动换算，也不采用自动换算加独立价格覆盖。修改一种币种售价不自动改写其他币种售价或历史成交记录，不引入汇率定价服务。

用户在 Q61 选择 A：每个 SKU 可按需配置部分启用币种的售价，不要求配齐全部启用币种才能上架。缺少某币种售价时，该 SKU 不能以该币种购买；服务端拒绝缺价购买，不将缺价当作零元或自动换算补价，也不因此阻止其在已有售价的币种销售。

用户在 Q62 选择 A：单笔订单固定使用一种交易币种，商品、优惠、运费、税费和总额均使用该币种；不同订单可采用不同交易币种，不支持一单混合币种。服务端按此约束计价，历史快照及导出保留订单交易币种，不直接相加不同币种金额。

用户在 Q63 选择 A：购物车切换币种时，有目标币种售价的商品按独立售价重新报价，缺价商品保留并标记不可购，不自动移除。用户移除缺价商品或切回可购币种后才能结算，服务端执行相同约束；不以零元补价或静默跳过缺价商品下单。

Q64 已确认登录时自动合并匿名与当前账号购物车，同 SKU 数量相加并重新校验价格库存。用户在 Q65 选择 A：两份购物车币种不同时，合并沿用登录前当前匿名购物车币种，全部商品按该币种独立售价重新报价；缺价商品沿用 Q63 的保留与结算阻断规则，不按汇率换算旧报价。

## 待细化边界

- Q66 已确认匿名购物车在当前浏览器保存，账号购物车由服务端保存并可跨设备继续使用。Q67 已确认默认匿名保存 30 天、账号保存 90 天，均从最后修改起计时，允许按站点配置，过期清理不影响历史订单；Q68 已确认同 SKU 数量冲突时拒绝基于旧内容的修改并提示刷新确认。配置变更的生效规则等细节留待后续电商设计，不作为 demo 的当前问题。
- 优惠/税费/运费的计算、退款及运营汇总继续设计；一单一种交易币种与切币缺价处理不替代这些业务规则。
- 展示币种、交易币种与服务商结算币种分别定义。开放币种和渠道组合需要按站点配置及选定服务商能力验证，不承诺任意币种均可使用。
- 完整数据导出及双平台恢复继续保留各币种独立售价、历史金额和关系，沿用 [ADR-0010](0010-customer-owned-hosting-and-portable-data.md)；不在本轮选择支付服务商，展示换算和服务商结算不由此定价规则代替。

需求、候选模型与验收见 [电商设计](../commerce.md) 和 [需求记录](../requirements.md#6-澄清顺序与记录)。本轮只更新设计文档，未实施定价、支付或汇率调用。
