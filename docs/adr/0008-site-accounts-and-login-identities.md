# 本站前台账号支持多种登录身份，登录后验证并主动绑定

用户确认 Google、微信和邮箱可以绑定同一个本站前台账号。用户登录后，验证并主动绑定新的登录身份；随后通过任一已绑定方式登录，都使用同一账号及其订单。

因此，本站前台账号与登录身份分别建模：前者承载用户资料和业务关联，后者提供登录该账号的入口。普通绑定将尚未归属其他账号的身份关联到当前账号，不另建账号，也不因登录渠道变化转移订单。未绑定身份的首次登录继续遵循验证成功后自动创建本站账号的流程。

目标登录身份已绑定另一个本站前台账号时，拒绝绑定并提示使用原账号；首版不提供账号合并。即使用户能验证两个账号，绑定流程也不合并账号或转移身份、资料与订单，两个账号原有的关联保持不变。

## 后续设计约束

- 绑定需要当前账号登录状态及对新身份的验证；具体接口、身份唯一性与并发处理待设计。
- 首版绑定冲突按拒绝处理，不提供主账号选择、账号合并或跨账号身份转移；解绑流程另行明确。
- 绑定不改变站点账号的业务权限，也不授予后台成员身份；前台账号与后台成员的关系仍按 [ADR-0006](0006-required-admin-optional-visitor-accounts.md) 分别定义。

登录渠道、自动注册与候选验收见 [用户管理与 CRM](../users-crm.md)，订单关联见 [电商需求](../commerce.md)。
