# CRM 与电商强制依赖用户管理，必需依赖自动安装并联动启用

用户确认 CRM 必须依赖用户管理，并要求安装插件时自动安装其依赖。依赖由插件声明，构建流程递归补齐必需依赖；操作人选择 CRM，即将用户管理一并纳入站点交付物，无需手动逐个选择依赖插件。对依赖 CRM 的其他插件，同样沿依赖链自动带入用户管理。

用户进一步确认运行时自动联动启用：启用插件时自动启用其已安装的必需依赖，并检查配置与就绪状态。CRM 与用户管理都已安装时，操作人只需启用 CRM，系统自动联动启用用户管理；用户管理未就绪时，CRM 不能被标记为已启用。

停用采用依赖保护规则：插件仍被其他已启用插件必需依赖时，拒绝停用并列出依赖者，要求操作人先停用依赖者。CRM 启用期间请求停用用户管理会被拒绝，两个插件保持原启用状态；不自动联动停用 CRM 或其他依赖者。

用户进一步确认电商同样强制依赖用户管理，遵循自动安装、联动启用和停用保护规则。CRM 与电商共用用户管理时，任一依赖者仍启用都阻止停用用户管理；不因先停用其中一个就解除其他依赖关系。

这一选择保留 CRM 与电商的可选组装边界，同时保证安装结果包含所需用户管理能力。用户管理可以单独安装；未选择 CRM、电商或其他依赖者的站点，仍可不安装用户管理。后台成员登录与授权继续由每站必备基础能力提供。

## 后续设计约束

- 自动安装发生在构建阶段；运行时启用操作不下载或安装插件代码。
- 安装与启用分别执行；自动安装代码不代表立即开放业务。自动联动启用仍需满足配置、依赖就绪及操作授权要求。
- 依赖保护通过后，仍需满足插件自身在途业务等停用条件；具体业务处理、从构建中移除、联动启用部分失败后的保留或补偿，以及重试恢复规则继续明确。
- 安装用户管理不等于为每个 CRM 联系人创建登录账号，联系人与账号的关联按各自业务规则设计。
- 买家下单登录要求已确认：所有电商站点未登录可浏览商品和加入购物车，提交订单前必须登录，不提供访客购买或按站点开放未登录购买的配置；登录后的购物车衔接规则待设计，具体业务规则见 [电商需求基线](../commerce.md)。具体哪个电商插件声明直接依赖，在电商包粒度设计时确定，不预设每个子模块都直接依赖用户管理。
- 依赖声明格式、版本解析与冲突处理待设计，候选规则与验收见 [插件生命周期](../plugins.md)。

业务职责和账号边界见 [用户管理与 CRM](../users-crm.md) 与 [电商需求基线](../commerce.md)。
