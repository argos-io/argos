# Argos 仓库组织

状态：三个并列的独立仓库及远端已就绪。更新：2026-11-09。

## 目录和仓库职责

三个仓库在开发工作区内并列放置，父目录的位置和名称由开发环境决定，仅用于归置仓库，不承担总仓库职责。下图的 `workspace/` 是示意名称，不要求实际使用该名称。

```text
workspace/
├── argos/                     # 已有仓库，保留需求与设计，独立 .git
├── core/                      # 核心系统，独立 .git
└── plugins/                   # 插件与主题，独立 .git
```

项目名称继续使用 Argos。核心系统仓库命名为 `core`，插件仓库命名为 `plugins`，实现仓库名不添加项目名前缀。已有 `argos` 仓库承载设计文档。

每个仓库拥有完整的 Git 元数据、历史、提交与远端，分别克隆、提交和发布。仓库之间不嵌套，不登记 Git submodule。

文档、规范和项目上下文/进度记录使用仓库相对路径，跨仓库引用以本工作区的并列布局为基准，不写死开发机绝对路径、用户目录或路径别名关系。工具执行时从实际检出位置确定仓库根目录，需要外部目录时由显式配置提供；交付源码不得依赖开发工作区的位置。

| 仓库 | 内容 | 维护边界 |
| --- | --- | --- |
| `argos` | 总体与两套产品需求、领域术语、契约设计、调研和决策 | 记录已确认要求和待定方案，与实现仓库分别提交 |
| `core` | 内部管理端基础、站点运行时、业务后台宿主及插件和主题契约 | 由独立核心维护流程开发和发布，操作人及站点生成任务不修改核心 |
| `plugins` | 业务插件、供应商适配器、主题及对应管理功能 | 通过核心公开契约扩展，不复制或分叉核心实现 |

核心仓库可以按实现需要分包，管理端与站点交付物仍保持产品边界。主题属于插件仓库；一个插件的业务实现、必要管理 UI、配置与迁移等应可追溯到其版本。Demo 的包目录与构建基线已列入[技术方案](demo-design.md)和[首批任务](demo-tasks.md)，契约 0.1 已通过本地双目标验证，远端包发布机制尚未实施。

## 当前布局评估

当前三个仓库分别承载设计决策、稳定核心与可复用业务资产，符合已确认的独立维护及生成任务不改核心的边界。Demo 阶段建议保留仓库名称和并列布局，无需增加总仓库、submodule 或继续拆分仓库。

- `core` 内部沿用首批任务中的 `apps/manager/`、`packages/site/`、`packages/admin-ui/` 和 `tools/` 职责。管理端与交付运行时按依赖和打包边界隔离；Node.js 与 Cloudflare 适配先在站点包内按目录区分，不为尚未验证的抽象预建独立包。
- `core/vendor/tailadmin/` 保留固定修订的完整开源模板及轻量组件入口，与 Argos 业务代码分开；完整示例的原始依赖声明保留在模板内，应用只安装实际引用组件所需的依赖。源码交付包含这一固定依赖，不依赖开发机外部路径。
- `plugins/extensions/` 与 `plugins/themes/` 区分业务插件和主题，单个插件的业务、后台组件及清单随同一版本维护。这里存放共享资产；agent 生成的项目插件留在受管理项目中，不自动回写共享仓库。
- 工作目录、预览数据、日志、构建缓存和交付快照由负责运行的项目在忽略目录中管理，当前统一保存在执行仓库的 `.local/`，避免进入设计仓库或共享插件源码。交付时仍按技术方案提供独立源码与数据包。
- 多仓库增加了契约、版本和文档同步成本。设计与进度继续以 `argos` 为入口，实现仓库保留就近使用说明；固定版本组合及跨仓库集成验证随 T0–T5 落实，不能以本地相邻源码代替可追溯依赖。

## 依赖与协作

站点交付工程由管理端使用固定版本核心、所选插件、主题和组装配置产出，不把内部管理端交给客户。多个仓库的版本组合由生成工程的依赖和构建记录确定，具体版本锁定与发布机制在技术设计中落实。

跨仓库变更在各自仓库检查差异和提交；需求与扩展契约变化需同步设计文档。操作人只组装插件、创建或编辑插件和主题，核心缺少扩展点时交由独立核心维护流程处理。

## 本地迁移与远端状态

`argos` 沿用已有仓库的 Git 历史和远端 `argos-io/argos`，设计文档迁回该仓库。此前独立设计仓库的提交通过 `migration/design-history` 标签保留，`paas` 备份分支及历史引用一并保留在 `argos`。

`core` 从原核心骨架提交继续开发，远端为 [argos-io/core](https://github.com/argos-io/core)；`plugins` 保留原插件仓库历史，远端为 [argos-io/plugins](https://github.com/argos-io/plugins)。这两个远端已创建为私有仓库，各自的 `master` 分支及其历史已推送，并设为默认分支。三个仓库分别克隆即可，私有仓库需要相应的访问权限。

迁移检查覆盖文档完整性、Git 引用保留、仓库独立性、远端配置、工作区路径及文档命名。迁移前完整快照保存在 `argos/.git/argos-migration/` 中，不作为项目源码交付。历史项目仅作为备份保留，不作为 Argos 新核心或插件实现。
