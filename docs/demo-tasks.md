# 可行性 demo：首批实现任务

状态：范围与技术方向已确认，任务已拆分，待执行确认；全部任务尚未开始。更新：2026-11-08。依据为[已确认范围 DM1–DM6](requirements.md#82-已确认-demo-完成标准)、[技术方案](demo-design.md)及 [ADR-0013](adr/0013-astro-site-host-and-plugin-boundaries.md)。

本清单是从设计进入编码的执行入口。按 T1→T5 推进，每项交付一个可运行结果；只在出现影响已确认范围或公共边界的新问题时再请求产品决策。实现、自动验证和外部真实验收分别记录，缺少外部配置不阻塞能独立完成的开发，也不能将相关验收标为通过。

## 1. 实现归属与约束

| 位置 | 本期实现归属 |
| --- | --- |
| `core/packages/site/` | 契约、运行时、Astro integration、Hono 请求链及 Node.js/Cloudflare 资源适配，按目录分工，先不为每个单元单独建包 |
| `core/packages/admin-ui/` | 独立后台宿主、导航和插件 React 组件接入 |
| `core/apps/manager/`、`core/tools/` | 内部工作台、任务及执行器、版本、构建预览与交付工具 |
| `plugins/extensions/`、`plugins/themes/` | 基础内容、必需 RBAC 和 Astro 企业主题；演示公告由 agent 在受管理项目中生成，不预写后冒充生成结果 |
| 项目内忽略目录 | 工作目录、SQLite/文件数据、日志、预览和源码快照；固定核心只读，不使用或覆盖当前未提交改动 |
| `argos/docs/demo-tasks.md` | 持续更新任务状态、真实验证证据及剩余外部条件 |

新增依赖按技术方案固定版本、检查 peer 与许可证并生成锁文件；不发布 npm 包、镜像或其他远端制品，不修改用户全局工具。测试脚本在 T1 建立，文中验证项不是当前已存在的可执行命令。

## 2. 执行任务

- [ ] **T1：在 Node.js 跑通可组装的企业展示站。**
  - 在 `core` 建立最小工程、统一构建/类型检查/测试入口及契约 `0.1`；契约覆盖清单、必需依赖、页面/API/后台注册、记录和文件访问。
  - 在 `plugins` 实现基础企业内容插件和 Astro 企业主题；核心根据声明注册页面和 Hono API，组装过程不为站点修改核心。
  - 接入 SQLite 和文件目录，使用开发初始化数据展示内容；认证完成前不开放未保护的后台写入接口。
  - 验证清单解析、缺失/循环/版本不兼容依赖拒绝、公开页面实际读取持久内容、构建和进程重启后的可用性。
  - **完成证据：**固定源码及清单、可运行 Node.js 站点、可重复的核心/插件验证记录；独立样例测试不计为真实 agent 生成。
  - _验收关联：DM3、DM5；需求 R2、R16、R20、R31、R79。_

- [ ] **T2：从站点后台真实登录并维护内容，验证角色授权。**
  - 实现 Google OIDC、受一次性凭据保护的首个管理员初始化、服务端会话及部署侧邀请命令；加入只读成员，不建设完整邀请管理界面。
  - 实现必需 RBAC 插件、`owner` 和只读普通角色；角色关联、初始化及后台业务写入满足两端共同的原子操作边界。
  - 实现 React 后台宿主和内容插件编辑组件，后台修改后公开页面按请求读取最新内容；身份、授权、插件状态和版本在服务端检查。
  - 验证未登录、只读越权、初始化重放、无效身份校验、CSRF、旧修订提交和存储失败；测试用身份桩仅用于自动测试，不作为 demo 登录替代品。
  - **完成证据：**Node.js 的后台内容操作及 API 拒绝记录；实际 Google 初始化和只读成员登录单独留证，缺少应用配置时明确未验收。
  - _验收关联：DM4；需求 R35、R51、R53、R60、R78。_

- [ ] **T3：同一套站点代码在 Workers 跑通，验证依赖和启停。**
  - 接入 Astro Cloudflare adapter、D1 和 R2；隔离平台特定入口及资源上下文，不将 Node.js 存储实现打入 Worker 路径。
  - 以同组用例验证参数绑定、原子批次失败回滚、条件写入冲突、初始化并发保护和服务端授权，不把零行更新当作成功。
  - 完成按声明补齐依赖、联动启用、配置就绪检查和被依赖时的停用保护；可停用插件的数据保留，维护入口仍可重新启用。
  - 用测试插件验证停用后公开页面、直接 API、后台入口一致生效；内容不通过静态 HTML 或动态缓存绕过检查。最终公告场景在 T4/T5 使用真实生成结果复验。
  - **完成证据：**相同源码/清单的两个构建、本地 Workers 与 Node.js 对照记录；云端测试部署和真实 D1/R2 行为单独记录，资源创建与部署需相应明确授权。
  - _验收关联：DM3–DM5；需求 R3、R37、R38、R53、R79。_

- [ ] **T4：工作台驱动真实生成公告插件，继续修改并形成新预览。**
  - 实现单个内部操作人、一个演示项目和串行任务：需求输入、插件选择、持久任务/有序事件、可重连进度、变更摘要、构建结果及独立来源的预览。
  - 接入固定 Codex SDK 和执行节点，核心及依赖只读，写入仅限项目插件、主题和组装配置；对越界变更和核心校验失败拒绝构建交付。
  - 从未包含公告实现的项目输入开始，由真实 agent 生成公告业务、权限、Astro 页面、React 后台注册和依赖声明；独立执行类型检查、测试与构建，不以模型自述判定完成。
  - 提出一次主题或插件修改，绑定明确输入版本和线程，形成新源码/构建/预览；验证失败、取消和服务重启不覆盖上一份成功版本，修复最多两轮。
  - **完成证据：**两次真实任务输入、脱敏事件、源码差异、未变的核心校验值、构建与两个可定位版本；真实生成需可用的 Codex 认证与额度，模拟事件不计入完成。
  - _验收关联：DM1–DM3；需求 R18、R21、R30、R31、R78。_

- [ ] **T5：交出独立源码，并恢复演示数据到全新目标。**
  - 固定所选交付版本，打包运行时、插件、主题、固定依赖源码/锁文件及配置和运行说明；排除内部工作台、SDK、凭据、日志和测试数据。
  - 在受控维护模式导出该版本实际持有的全部业务记录、关系、配置和实际文件，记录模式/插件版本、引用及校验值；未知模块、缺文件或不兼容版本必须失败。
  - 分别执行 SQLite→D1、D1→SQLite 及同平台新存储恢复；保留成员角色、内容/公告关系及初始化完成事实，生成新会话世代，不重放失效凭据。
  - 在干净环境运行源码，关闭管理端与 agent、断开源存储，完成公告发布/读取、只读拒绝、依赖/启停及文件读取；只有目标资源实际独立运行才算恢复成功。
  - **完成证据：**可交接源码包、数据包完整性报告、目标运行和恢复记录、一次完整 demo 演示；所有 DM1–DM6 明确通过或未通过，不将本地模拟记录标为真实云端成功。
  - _验收关联：DM1–DM6；需求 R3、R8、R19、R63、R78、R79。_

## 3. 外部条件与启动边界

T1 可以先执行，无需云账户、Google 或模型凭据。T2 的真实登录需要 Google 测试应用及回调配置；T3/T5 的真实云端验证需要获授权的 Workers/D1/R2 测试资源；T4 的真实生成需要可用 Codex 认证。凭据通过受控环境配置，不粘贴到对话、源码或验证日志。

正式执行前确认本任务计划；执行后在此文件勾选并附证据。只完成代码而未完成对应真实验收时，应分别说明，不直接将整个任务标为完成。生产发布、资源删除、远端制品推送和客户数据操作不在本轮设计或默认编码授权内。
