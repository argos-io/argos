# 可行性 demo：首批实现任务

状态：范围与技术方向及 Q73–Q75 已确认，[设计审查](demo-review.md)后的契约和验证顺序已修订，待执行确认；全部实现任务尚未开始。更新：2026-11-09。依据为[已确认范围 DM1–DM6](requirements.md#82-已确认-demo-完成标准)、[技术方案](demo-design.md)及 [ADR-0013](adr/0013-astro-site-host-and-plugin-boundaries.md)。

本清单是从设计进入编码的执行入口。先执行 T0 的本地双目标和原子命令门槛，再推进 T1–T5；最小真实执行器验证在认证条件就绪后尽早执行，须早于 T4 的完整工作台。只在出现影响已确认范围或公共边界的新问题时再请求产品决策。实现、自动验证和外部真实验收分别记录；T0 的外部执行器小项缺少配置时可保留未验证，本地门槛通过后仍可推进独立的站点开发，不能因此将整个 T0 勾选完成。

## 1. 实现归属与约束

| 位置 | 本期实现归属 |
| --- | --- |
| `core/packages/site/` | 契约、运行时、Astro integration、Hono 请求链及 Node.js/Cloudflare 资源适配，按目录分工，先不为每个单元单独建包 |
| `core/packages/admin-ui/` | 独立后台宿主、导航和插件 React 组件接入 |
| `core/apps/manager/`、`core/tools/` | 内部工作台、任务及执行器、版本、构建预览与交付工具 |
| `plugins/extensions/`、`plugins/themes/` | 基础内容、必需 RBAC 和 Astro 企业主题；演示公告由 agent 在受管理项目中生成，不预写后冒充生成结果 |
| 项目内忽略目录 | 工作目录、SQLite/文件数据、日志、预览和源码快照；固定核心只读，不使用或覆盖当前未提交改动 |
| `argos/docs/demo-tasks.md` | 持续更新任务状态、真实验证证据及剩余外部条件 |

新增依赖按技术方案固定版本、检查 peer 与许可证并生成锁文件；首次安装默认阻止依赖脚本，检查后只开放必要项，核查依赖审计结果；不发布 npm 包、镜像或其他远端制品，不修改用户全局工具。测试脚本在 T0 建立，文中验证项不是当前已存在的可执行命令。

## 2. 执行任务

- [ ] **T0：先验证双目标接入、受条件约束的命令及最小执行器。**
  - 建立最小固定依赖工程和验证入口，用样例逻辑页面、Astro 呈现/主题布局、React 后台组件和 Hono API，证明同一静态清单在 Node.js 与本地 Workers 构建并请求通过；Worker 入口不包含 Node.js 存储实现。
  - 用 SQLite 与本地 D1 对照验证每次全新执行标记、全写入受本次标记控制、批次内断言及失败回滚；覆盖无授权、停用、维护、旧修订均不写入，历史幂等键不得复用旧标记绕过撤权，改动输入拒绝，幂等结果读取仍复核身份，以及并发初始化仅一次。Node.js 内存原语已有验证，不代替真实适配实现。
  - 前两项是冻结契约 `0.1` 及 T1 正式站点实现的门槛；失败时先收敛最小复现，确需改变已确认架构边界再提交具体取舍，不先扩展业务或界面。
  - 可用 Codex 认证就绪时，尽早在目标容器运行一个最小真实任务，验证核心/依赖只读、明确可写范围及构建缓存、非交互失败、取消与进程退出；缺外部条件时明确待验，完整工作台 T4 不先行替代此验证。
  - **完成证据：**双目标最小构建/请求及原子性对照记录，单独列出真实 SDK 任务结果或缺失条件；样例不包含预写公告实现，不计入 DM1 的真实生成。
  - _验收关联：DM1、DM3、DM5 的技术门槛；需求 R2、R3、R16、R21、R31、R53、R79。_

- [ ] **T1：在 Node.js 跑通可组装的企业展示站。**
  - 基于 T0 通过的工程收敛契约 `0.1`；覆盖清单、必需依赖、逻辑页面/呈现映射、API/后台注册、记录类型/数据模式、显式引用和受保护记录/文件命令。
  - 在 `plugins` 实现基础企业内容插件和 Astro 企业主题；静态映射确定唯一页面及布局，冲突、未知覆盖与保留路径覆盖均失败，组装不修改核心。
  - 接入 SQLite 和文件目录，使用开发初始化数据展示内容；认证完成前不开放未保护的后台写入接口。
  - 验证清单解析、缺失/循环/版本不兼容依赖拒绝、公开页面读取持久内容、构建重启及路径规范化检查；文件目录不作为公开静态资源挂载。兼容检查覆盖旧记录和文件引用，需要转换已有数据时明确暂停，不实现迁移执行器。
  - **完成证据：**固定源码及清单、可运行 Node.js 站点、可重复的核心/插件验证记录；独立样例测试不计为真实 agent 生成。
  - _验收关联：DM3、DM5；需求 R2、R16、R20、R31、R79、R81。_

- [ ] **T2：从站点后台真实登录并维护内容，验证角色授权。**
  - 实现普通邮箱邀请与一次性链接确认/登录、受一次性初始化凭据加邮箱验证保护的首个管理员流程、服务端会话和部署侧受保护邀请命令；只邀请普通只读成员，不建设完整邀请管理界面。
  - 实现必需 RBAC 插件、`owner` 和只读普通角色；角色关联、初始化及后台业务写入满足两端共同的原子操作边界。
  - 实现 React 后台宿主和内容插件编辑组件，后台修改后公开页面按请求读取最新内容；身份、授权、插件状态和版本在服务端检查。
  - 验证链接过期、重放、撤销、用途混用、邮件扫描 GET 不消费、确认 POST 的来源/CSRF、发送失败、未登录与只读越权、初始化并发、旧修订和存储失败；普通登录不自动授予成员资格，测试身份或邮件桩仅用于自动测试。
  - **完成证据：**Node.js 的后台内容操作及 API 拒绝记录；实际邮件初始化、邀请确认及后续链接登录单独留证，缺邮件配置或发信未就绪时明确未验收。
  - _验收关联：DM4；需求 R35、R51、R53、R60、R78、R83。_

- [ ] **T3：同一套站点代码在 Workers 跑通，验证依赖和启停。**
  - 在 T0 本地基础上完成 Astro Cloudflare adapter、D1 和 R2 的真实业务适配；隔离平台入口及上下文，显式约束图片服务，不隐式增加 Images 资源。
  - 以同组用例验证参数绑定、原子批次失败回滚、条件写入冲突、初始化并发保护和服务端授权，不把零行更新当作成功。
  - 完成依赖补齐、完整链配置检查及原子联动启用，依赖未就绪时本次全部状态保持不变；停用与并发启用协调，数据保留，维护入口可重新启用。
  - 用测试插件验证停用后页面、直接 API、后台和业务文件入口一致生效；可选公告区块关闭不影响企业首页。验证私有 R2、草稿文件拒绝、文件暂存/引用失败及维护冻结，复用邮箱认证测试；最终公告场景在 T4/T5 使用真实生成结果复验。
  - **完成证据：**相同源码/清单的两个构建、本地 Workers 与 Node.js 对照记录；云端测试部署和真实 D1/R2 行为单独记录，资源创建与部署需相应明确授权。
  - _验收关联：DM3–DM5；需求 R3、R37、R38、R53、R79。_

- [ ] **T4：工作台驱动真实生成公告插件，继续修改并形成新预览。**
  - 基于 T0 已验证执行器实现单个内部操作人、一个项目和串行任务：需求输入、插件选择、持久任务/有序事件、可重连进度、变更、构建及预览。工作台使用独立访问凭据并校验 Host、来源/CSRF；预览使用不同主机名及独立凭据，不共享父域 cookie，验证来自预览的管理操作被拒绝。
  - 接入固定 Codex SDK 和执行节点，核心及依赖只读，写入仅限项目插件、主题和组装配置；对越界变更和核心校验失败拒绝构建交付。
  - 从未包含公告实现的输入开始，由真实 agent 生成公告业务、权限、Astro 呈现组件、主题页面映射、React 后台注册和依赖声明；独立执行类型检查、测试与构建，不以模型自述判定完成。
  - 提出一次主题或插件修改，绑定明确输入版本和线程，形成新源码/构建/预览；同一目标的预览沿用共享测试数据和文件，验证续改后已录入内容保留，旧版源码及构建记录可定位。生成与自动验证使用独立工作/测试目录，不直接写共享业务数据；接入前检查模式兼容。验证失败、取消和服务重启不覆盖上一份成功版本，修复最多两轮。
  - 验证需要转换旧数据的修改被暂停且不重置数据；绑定执行进程/容器，取消或服务重启后核实旧执行已退出，再开放下一任务；无法确认退出时项目保持中断。
  - **完成证据：**两次真实任务输入、脱敏事件、源码差异、未变的核心校验值、构建与两个可定位版本；真实生成需可用的 Codex 认证与额度，模拟事件不计入完成。
  - _验收关联：DM1–DM3；需求 R18、R21、R30、R31、R78、R80、R81。_

- [ ] **T5：交出独立源码，并恢复演示数据到全新目标。**
  - 固定所选交付版本，打包运行时、插件、主题、固定依赖源码/锁文件及配置和运行说明；排除内部工作台、SDK、凭据、日志和测试数据。
  - 在受控维护模式导出站点在明确切点持有的全部业务记录、关系、配置和实际文件，核验所选交付源码与当前数据兼容，记录切点、模式/插件版本、引用及校验值；未知模块、缺文件或不兼容版本必须失败，不将旧源码版本记录当作历史数据快照。
  - 维护冻结覆盖上传、关联、删除、清理和后台写入，处理在途上传，导出包含停用插件及全部已提交文件；未提交暂存对象单独报告。恢复实际复制文件并校验引用，不依赖源存储 URL。
  - 分别执行 SQLite→D1、D1→SQLite 及同平台新存储恢复；保留成员角色、内容/公告关系及初始化完成事实，生成新会话世代，不重放失效凭据。
  - 在干净环境运行源码，关闭管理端与 agent、断开源存储，完成公告发布/读取、只读拒绝、依赖/启停及文件读取；只有目标资源实际独立运行才算恢复成功。
  - **完成证据：**可交接源码包、数据包完整性报告、目标运行和恢复记录、一次完整 demo 演示；所有 DM1–DM6 明确通过或未通过，不将本地模拟记录标为真实云端成功。
  - _验收关联：DM1–DM6；需求 R3、R8、R19、R63、R78、R79、R81、R83。_

## 3. 外部条件与启动边界

T0 的本地双目标/命令门槛可以先执行，无需云账户、邮件或模型凭据；它通过后可推进独立的站点开发。T0 的真实执行器和 T4 需要 Codex 认证，尽早核验；T2 的真实初始化、邀请及登录需要邮件服务、发信身份与受信任站点地址；T3/T5 云端验证需要获授权的 Workers/D1/R2 测试资源。Google 测试应用不再是本期必需条件。凭据通过受控环境配置，不粘贴到对话、源码或验证日志。

本轮已完成 [DR1–DR8](demo-review.md) 的需求澄清、契约补充和前置验证计划修订，尚未获得 Q72 的任务执行确认。确认后从 T0 开始编码并在此文件勾选、附证据；任何真实验证失败按门槛处理，不把设计补充当作实测通过。后续标准数据迁移草案不纳入本期。只完成代码但缺少真实验收时分别说明，不能将整个任务标为完成；生产发布、资源删除、远端制品推送和客户数据操作仍需具体授权。
