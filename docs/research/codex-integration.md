# Codex：管理端编码 agent 集成参考

调研日期：2026-11-06。仅依据官方 OpenAI documentation；未安装 SDK、调用服务或完成集成验证。具体能力与兼容性以实施时固定版本为准。

后续进度：本文件保留原入口调研；当前 demo 的执行基线已采用 TypeScript Codex SDK，接口与发布包核对见 [demo-design.md](../demo-design.md)，实现验证见 [首批任务](../demo-tasks.md)。下述 SDK/app-server 比较不作为当前重复澄清项，仍不声明已完成真实集成。

## 已确认的产品要求

管理端采用 Web 工作台，由 agent 执行站点及插件生成，可以使用成熟 agent SDK，用户以 Codex 为例。管理端自身部署不限定 Cloudflare。这些要求不等于已经选定 Codex SDK、app-server、某个模型或某种托管执行方式。

## 官方集成入口

| 入口 | 官方文档说明 | 对本项目的参考意义 |
| --- | --- | --- |
| [Codex SDK](https://learn.chatgpt.com/docs/codex-sdk) | 提供程序化控制本地 Codex agent 的方式；TypeScript 库在服务端运行，可启动、继续和恢复线程 | 可用于管理端发起编码任务；具体依赖、执行环境和任务控制能力需固定版本验证 |
| [Codex app-server](https://learn.chatgpt.com/docs/app-server) | 用于自定义客户端与 Codex 交互；相关集成说明包含会话和事件等客户端能力 | 若工作台需要持续交互与执行过程控制，作为候选评估 |
| [Codex 平台集成说明](https://developers.openai.com/blog/codex-as-a-platform) | 区分程序化任务的 SDK 与需要持续会话、流式事件和任务交互的 app-server 集成 | 用工作台实际需求比较入口，而非仅根据 SDK 名称做选择 |

文档中的“线程”是供应商集成概念，与本管理端的项目、任务、源码版本和交付版本分别建模。

## 设计建议与选型验证

- 工作台 UI、管理服务和工程执行能力分工明确，agent 集成放在管理端执行路径中。
- 优先验证一个实际集成入口，使用薄适配承接任务输入、进度、输出与失败，暂不设计通用多 agent 平台。
- 验证能否读取项目上下文、生成站点和带后台扩展的插件、执行工程构建，并保留源码变更及验证结果。
- 分别验证持续对话、事件展示、中断和恢复；不假设所有 SDK 具有相同能力。
- 管理端保存项目、任务与交付事实；交付站点不携带 SDK 或生成环境依赖。
- 具体执行节点、工程存储、SDK 与服务版本、模型、认证、费用和并发限制仍待选型，不作当前可用账户或预算承诺。

上述是本项目设计推论，不是官方对本项目架构或部署平台的建议。
