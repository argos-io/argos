# Argos 主题与操作边界

状态：操作人范围和主题定位已确认；具体契约为讨论稿。更新：2026-11-07。

## 已确认要求

- 操作人只按需组装插件、创建或编辑插件、创建或编辑主题。
- 主题可视为插件的一种，负责页面、布局、视觉和内容呈现。
- 核心系统代码不随站点需求调整，管理端的生成与修复任务不修改核心代码。
- 插件和主题存放在独立于核心的仓库，使用核心提供的稳定扩展契约。

## 职责划分

| 对象 | 职责 | 维护方式 |
| --- | --- | --- |
| 核心系统 | 通用管理端、站点运行时、后台宿主和扩展契约 | 核心维护者在核心仓库独立开发和发布 |
| 业务插件 | 业务模型、API、事件、任务及对应后台管理功能 | 操作人通过内部管理端创建或编辑，构建时安装 |
| 主题插件 | 站点页面、布局、样式、资源及业务插件呈现 | 操作人通过内部管理端创建或编辑，随构建交付 |
| 组装配置 | 选择核心、插件和主题版本，记录配置与目标环境 | 管理端按需求生成和维护，不修改核心实现 |

核心仓库可以同时维护管理端和交付运行时的基础工程，但两者仍是不同产品边界；不意味着将内部管理端打包交付给客户。具体包结构与语言技术栈尚未选择。

## 主题契约建议

- 声明主题 ID、版本、依赖的核心契约和所需业务插件。
- 通过核心的页面或渲染扩展点提供布局、组件、资源和可维护配置；具体前端框架尚未确定。
- 从业务插件契约获取商品、购物车、用户等数据并调用业务操作；交易事实与业务规则由业务插件维护。
- 主题随构建安装，运行时使用已安装且兼容的版本；多主题共存、激活和切换规则仍待设计。
- 按插件规则提供对应后台配置或状态管理。是否允许改变业务后台视觉，以及后台主题的契约范围，尚未确定。

## 生成任务边界

管理端准备固定核心版本，agent 按需求创建或编辑业务插件、主题及组装配置。构建和验证覆盖页面、后台扩展与所选业务功能，检查核心源码未被任务修改。

如果现有契约不能满足某需求，生成任务报告缺失扩展点或不兼容原因，交由独立核心维护流程处理；不自动修改核心、复制核心后针对单站点打补丁，或通过隐藏的项目分支改变核心行为。

这是工作流与可维护性边界，不改变操作人对注册插件安全性的责任。

## 候选验收

1. 使用同一核心版本组装不同插件与主题，生成两个不同风格及功能的站点。
2. 新增业务能力及后台管理通过插件注册完成，前台呈现通过主题完成，核心源码无差异。
3. 修改主题的页面和样式后重新构建预览，业务数据和插件契约仍按约定工作。
4. 插件或主题要求不存在的核心扩展点时，报告缺口，不改写核心以使构建勉强通过。
5. 交付记录可追踪核心、插件、主题和组装配置版本，具体记录形式待设计。
