# 站点业务后台与插件管理功能注册

状态：已确认独立后台交付与插件注册要求；注册契约和实现方案为讨论稿。更新：2026-11-07。

关联 [站点交付物](site-deliverable.md)、[管理端](management-system.md) 与 [插件生命周期](plugins.md)。

## 1. 已确认要求

- 最终站点交付物必须自带独立业务后台，随站点源码交付。
- 业务后台独立于站点生成与管理端，为交付站点提供日常业务操作。
- 插件不仅提供业务功能，还必须向业务后台注册对应管理功能。
- 插件在构建阶段安装，运行阶段可以控制启用状态；这一边界同样适用于其后台扩展。

管理端生成新插件时，需要同时生成相应管理功能和注册声明，构建发布后在交付站点中使用。

## 2. 通用后台与插件职责（建议）

| 部分 | 建议职责 | 应保持的边界 |
| --- | --- | --- |
| 后台宿主 | 布局、导航、路由承载、通用组件、身份与操作上下文、插件注册处理及状态展示 | 不硬编码商品、订单或 CRM 等每个模块的业务操作 |
| 插件业务实现 | 业务模型、查询、操作、事件、任务与数据迁移 | 业务规则由插件维护，后台 UI 和开放 API 调用相同业务规则 |
| 插件管理扩展 | 注册菜单、页面、表单、列表、详情、动作、配置及必要接口 | 与插件代码版本一起构建和交付，运行时按启用状态和业务权限开放 |
| 跨插件扩展 | 向其他插件已声明的详情区、工具栏或面板增加管理能力 | 显式声明依赖与扩展点，目标未启用时遵循可选适配规则 |

后台宿主可以来自运行时基础包或单独的管理基础模块，具体包边界待设计。独立业务后台是明确交付要求，不意味着把所有后台业务实现放入最小核心。

## 3. 候选注册契约

以下为设计建议，不是已经选定的代码接口。

| 注册项 | 建议内容 |
| --- | --- |
| 插件归属 | 稳定插件 ID、版本、管理扩展 ID 与依赖 |
| 导航 | 菜单、分组、标题、排序及关联页面 |
| 页面与组件 | 路由、列表、详情、表单、设置页及自定义管理组件 |
| 操作与 API | 查询、创建、修改、批量操作及业务命令；明确其业务服务与接口 |
| 业务权限 | 入口展示和操作所需的站点业务权限，与 API 授权语义一致 |
| 配置与状态 | 插件设置、依赖就绪情况、运行状态、错误及必要维护操作 |
| 扩展点 | 向其他插件的详情页、工具栏、面板或工作台贡献组件与动作 |
| 生命周期 | 启停、维护阶段、迁移与配置版本对管理入口的影响 |

管理 UI 的具体前端框架、自定义组件形式、通用表单生成和代码组织尚未选择。不要求所有管理界面只能由通用 CRUD 表单生成；商品规格、退款和客户互动等复杂操作需要合适的业务界面。

对于主要提供后台服务或 provider 适配的插件，对应管理能力可以是配置、连接状态和维护视图，不必为了注册要求创建无意义的业务列表。

## 4. 构建与运行时启停（建议）

- 构建时纳入插件业务代码、后台页面或组件、注册声明和必要接口，检查标识、路由及依赖冲突。
- 运行时启用插件后，按其依赖、配置和当前用户业务权限开放管理入口；注册声明与代码已经存在于交付物中。
- 运行时停用时，处理菜单、页面访问、管理操作和对应服务端入口，不能只隐藏导航。
- 对支付等有在途业务的插件，可按已明确的维护策略保留存量交易视图和处理动作，完整停用条件由插件契约定义。
- 后台宿主保留插件状态查询和恢复操作入口；停用业务插件不应导致无法查看或恢复其状态。
- 跨插件扩展跟随双方启用状态与依赖规则变化，不留下失效按钮或页面。
- 管理端调用开放 API 与站点业务后台操作，采用相同的业务状态检查和规则。

启停生效时限、缓存与多实例处理跟随统一插件生命周期方案，不在后台另建一套开关状态。

## 5. 首版插件管理功能示例

这些是对应业务范围的候选覆盖清单，操作细节继续随各模块需求澄清。

| 插件能力 | 对应后台管理示例 |
| --- | --- |
| 企业展示 | 企业资料、展示内容、媒体及已支持页面配置 |
| 主题 | 已安装主题、对应配置和兼容状态；主题源码的创建与编辑由内部管理端完成，业务后台不承担代码生成 |
| 外部客服接入 | 服务商配置、入口设置、连接状态；按对接能力提供会话或客户上下文链接 |
| 商品目录 | 分类、规格、变体、SKU、媒体、上下架和批量管理 |
| 订单、支付与库存 | 订单处理、支付状态、退款、库存调整与业务记录核对 |
| 市场与物流 | 商家和销售区域配置、物流账号与服务选择、运费规则、报价、面单、发货、轨迹与异常处理；按 provider 能力提供操作 |
| 用户管理 | 用户列表、资料、账号状态、后台成员及角色权限操作 |
| CRM | 客户档案、标签分群、负责人、跟进、互动记录、摘要和导入导出 |
| 后续销售管理 | 注册商机或销售流程界面，并向 CRM 客户详情增加销售扩展 |

## 6. 候选验收

- 交付站点在两种运行目标均提供业务后台，管理端不可用时仍能完成约定日常操作。
- 新增插件仅通过其注册契约增加管理功能，无需修改通用后台的专属业务分支。
- 未启用插件的管理能力按规则关闭；通过旧链接、API 或页面中的旧动作也不能绕过启停规则。
- 根据权限呈现可操作入口；前台组件与服务端返回使用相同业务规则。
- CRM 向客户详情注册扩展，停用对应插件后不留下失效入口；后台仍可查询插件状态。
- 插件配置、代码和迁移版本不匹配时，后台清楚展示原因，不将不可用能力显示为可正常操作。

后台路由约定、UI 技术、具体组件与权限矩阵在实施设计阶段确定。
